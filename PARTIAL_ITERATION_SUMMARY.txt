╠═══════════════════════════════════════════════════════════════════════════
║  ITEMS() PERFORMANCE: NOT A REAL-WORLD USE CASE
╠═══════════════════════════════════════════════════════════════════════════

  Scenario: From Beginning (using items())
    BPlusTreeMap: 38-40ms
    std::BTreeMap: 0.007ms
    Slowdown: 5,000x

  ROOT CAUSE:
    items() calls len() which walks all leaf nodes (O(n) operation)
    For 10M items: 78,125 leaf nodes × 200ns = 16ms

  WHY THIS DOESN'T MATTER:
    ✗ items() is NOT how you use a B+ tree in production
    ✗ Real applications use range(key..) to start from known positions
    ✗ Full iteration from the beginning is rare and discouraged
    ✓ Use range() instead - it's fast and idiomatic

  RECOMMENDATION:
    Don't use items() on large trees. Use range(first_key..) if you need
    to iterate from the beginning, or better yet, start from a meaningful key.
